# 舰队复原实施计划

2026-11-04 用户确认。覆盖 ROADMAP C1—C5，以及本模块所需的发布和验收。

## 优先原则

最关注船只本身的复原。先完成有辨识度的船体、甲板楼、桅帆、舵、锚、缆索和水密隔舱，再完善舰队展示。界面装饰、复杂动效和非必要展示细节不挤占建模工作。人物角色复原属于 D；本阶段只用简化人物作为比例参照。

数据分为史载、研究复原和建模假设。史料缺失的历史数字写 null，几何所需的假设参数单列，不将大船数、改造船数混称为舰队总数。没有依据的船型比例标为假设编成。

## 交付

- fleet.html：单船复原、历次舰队两个视图；沿用现有导航与昼夜配色。
- js/fleet-data.js：五类船型、尺度方案、构件说明、七次船数及出处。
- three/ships.js：参数化船体与主要构件，统一坐标和米制单位。
- three/scene.js：相机、灯光、海面、画质调整、资源释放。
- three/fleet.js：舰队布局、实例化与选择。
- three/fleet-page.js、css/fleet.css：交互与响应式布局。
- tools/check-fleet.mjs：数量、数据引用、模型尺寸和几何预算检查。
- 舰队离线版、页面入口、README 与接口规范更新。

## 阶段 1：资料与参数（C1、C4）

1. 核查现有七次船数资料；检索原始文献及可信研究，记录书名、卷次或论文定位与来源链接。
2. 核实五类船型用途、宝船尺寸争议、单位换算及主要构件依据。
3. 将史载数量、研究解释、建模假设分开保存。不能核实的研究尺度不标作学界定论。
4. 七次舰队分别提供记载数量与假设编成；缺失数字不冒充真实船数。
5. 同步 SPEC：buildShip(typeId, options)，+X 船首、+Y 向上、+Z 右舷、水线 y=0。

验收：关键数字有出处，假设有说明，页面与模型读取同一份参数。

## 阶段 2：先做单船主体（C2、C3）

1. 宝船样板：横剖面船体、抬升首尾、甲板、楼舱、舷墙、桅杆、硬帆及帆骨、主要索具、舵、锚。
2. 船体剖视：显示隔舱与甲板结构；剖面本身明确为示意。
3. 扩展马船、粮船、坐船、战船，按用途和假设参数体现比例与结构区别。
4. 提供高、中、低三档细节；高细节单船少于 30,000 三角面。
5. 基本交互：旋转缩放、常用视角、构件热点及文字列表、尺度切换、人物/场地比例参照。

验收：五类船主体完整，模型实际尺寸与标注一致，船首方向和水线正确。先检查船本身，再优化面板与动效。

## 阶段 3：七次舰队（C5）

1. 分组实例化，按船型、尺度和细节等级共享几何体。
2. 展示布局随船体尺寸调整，避免重叠；明确不是历史阵法复原。
3. 航次切换、记载/假设模式、船型筛选、选择船只进入单船。
4. 数量不明时保留资料说明，不用其他航次的数值代填。
5. 限制像素比、低帧率降级、不可见时暂停、销毁旧资源。

验收：场景船数与数据一致；250 艘桌面 50 fps 为目标，记录实测条件，不宣称未经测试的性能。

## 阶段 4：联动、离线与验收

1. 开放导航；档案船队页、航海图宝船专题增加入口；支持船型/航次直达。
2. 固定版本打包工具处理 ES 模块，生成舰队单文件并修正离线页面间跳转。
3. 无 WebGL 时仍保留全部文字资料与参数。
4. 数据/几何检查、现有航线回归；桌面 1440×900、手机 390×844 昼夜检查。
5. 检查热点、剖视、尺度、七次切换、刷新、离线、键盘操作、控制台和横向溢出。
6. 更新 ROADMAP 与 README，记录验证范围和遗留限制。

## 后续可选：港口环境复原

舰队与单船主体完成后，再适当增加港口环境。先选一个与航行直接相关的港口，核对岸线、码头和仓储等依据，提供船只靠泊的尺度与空间参照。环境以简化背景为主，不提前展开城市建模，不影响船只复原的完成和性能。具体港口和复原精度另行依据资料决定。
