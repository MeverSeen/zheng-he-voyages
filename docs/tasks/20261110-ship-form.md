## 目标

修订四项形制，五类船的参数化模型（`three/ships.js`）和宝船 Blender 母版、网页 GLB 保持一致：

1. 方艉与平板船首
2. 船体横剖面（尖底、圆舭、舷侧厚板）
3. 艉舵（悬挂升降舵、舵槽，按出土舵杆校核）
4. 不对称斜顶硬帆，主桅回到中线

**不在本任务内**：船楼样式、锚的样式、落帆开关、五类船的差异化、材质贴图、GLB 压缩、桅数（九桅保留为既有展示假设）、两套尺度的数值（61.2×13.8 米与《明史》折算不变）、七次舰队的数量数据。

## 现状（供定位，改之前自己再核对一遍）

- 船体轮廓由 `three/ships.js` 的 `shape(t)` 决定：`t=0` 是艉、`t=1` 是艏（船首朝 +X）。艉端半宽系数 0.34（约为船宽的 1/3），艏端 0.10；艏艉都用直立的横剖面多边形封口。
- 横剖面 `ring(t)` 只有 7 个点。
- 同一套轮廓在 `tools/blender/build-baochuan.py` 里又写了一遍（`shape`、`surface`），两处必须同步。
- 舵：`three/ships.js` 中"Stern rudder and head-stock"一段，一根直杆加一块板；舵杆长度约为 `1.3×干舷 + 1.25×吃水`。
- 桅位：`js/fleet-data.js` 的 `rigStations`，每项为 `[纵向位置/L, 横向位置/B, 桅高/L, 帆宽/L]`；九根里有七根偏离中线 ±0.20—0.24 船宽，包括最高的两根。
- Blender 流程：`npm run model:baseline` 由 `three/ships.js` 导出参数底稿并在 Blender 中精修生成 `models/baochuan/generated/baochuan-baseline.blend`；`models/baochuan/baochuan-master.blend` 是独立母版；`npm run model:export` 从母版导出 `assets/ships/baochuan-{full,section}.glb`。说明见 `models/baochuan/README.md`。

## 第 0 步：判断母版有没有手工编辑（决定母版怎么改）

母版按约定不能用生成脚本覆盖。动手之前先查清它是否含有脚本之外的手工修改：

1. 在**未改任何代码**的基线上，把底稿和母版重建到临时目录（不要写进仓库里的 `models/`、`assets/`）：先生成临时底稿，再对临时路径运行初始化（`init-baochuan-master.py` 支持 `--master`；底稿路径如果写死，就在临时工作副本里运行）。
2. 写一个一次性的 Blender 比较脚本（放 `tools/blender/compare-master.py`，可以提交），比较"临时重建的母版"与"仓库里的母版"：对象名集合、父子关系、每个网格的顶点数与面数、包围盒、修改器列表及主要参数、自定义属性、材质名。包围盒和顶点坐标允许 1e-4 米以内的浮点误差。
3. 结论只有两种，写进结果文件并附比较输出：
   - **A：没有手工编辑**（差异都在浮点误差内）。本任务允许用新底稿重新初始化母版：先 `git mv` 旧母版到临时名或直接删除后重新 `npm run model:init-master`，旧版本留在 git 历史里。提交信息里写明"母版由新底稿重新初始化，经比较确认此前无手工编辑"。
   - **B：有手工编辑**。**不要覆盖母版。** 只完成参数化模型、底稿（`generated/`）和下面的检查，母版与两个 GLB 保持原样，舰队页此时宝船精修模型与参数化模型形制不一致——在结果文件"需要负责人决定的问题"里列出差异对象清单，由负责人决定如何把修改带进母版。此时 `npm run build` 如因母版指纹检查报错，如实记录，不要绕过检查。

## 要做的事

建议按下面的顺序分提交。每个提交之后 `npm run check` 都要能通过。

### 1 方艉与平板船首（评审第 1 条）

- 艉封板：顶部宽度不小于该船型船宽的 55%，自下而上向后倾斜（上缘比下缘更靠后），上宽下窄。艉楼甲板可以伸出封板之上。
- 船首：改为上宽下窄的平板封首（搪浪板），顶部宽度约为船宽的 30%—40%，向前上方倾斜；不要做成尖艏。
- 总长仍以两套尺度的 L 为准（现有检查要求船体包围盒长度与 L 相差不超过 2%，宽度不超过 3%）。
- 五类船都用同一套新轮廓。

### 2 横剖面（评审第 1 条的延伸）

- 每个横剖面的点数增加到 13—15 个：龙骨处尖底，圆滑的舭部，舷侧向上略外飘。舯部最大宽度仍等于 B。
- 每舷加 2—3 道沿船长的突出厚板（大㯭），可见但不夸张。
- `tools/blender/build-baochuan.py` 中的轮廓与 `three/ships.js` 保持同一组系数；最好把系数放到一处（例如写进导出的 `baochuan-base.json` 的 metadata，由 Python 读取），避免以后再次分叉。
- 隔舱板、甲板、舱口、货物要跟随新的剖面，不能穿出船壳。

### 3 艉舵（评审第 2 条）

- 改成悬挂的升降舵：舵杆从艉部的舵槽（艉封板中线上的开槽）穿下，舵叶下缘低于船底线，舵叶面积比现在明显加大（梯形或长方形舵叶，可以有几道横向加强条）；舵柄从舵杆顶端向前伸到艉楼之下或之内。
- 把两套尺度下模型的舵杆长度算出来，写进 `ship.userData`（例如 `rudderStock`，单位米），并在 `js/fleet-info.js` 或 `js/fleet-data.js` 的"艉舵"构件说明里加一句：模型舵杆长度多少，1957 年南京宝船厂遗址出土铁力木舵杆长 11.07 米（该数字仓库中 `js/data.js` 已有，沿用同一说法）。
- **不要为了凑 11.07 米去改吃水、干舷或船长。** 两套尺度的舵杆长度是多少就写多少，差距照实说明；出土舵杆对应多大的船本身有争议，说明文字里不要下结论。

### 4 硬帆与桅位（评审第 3、4 条）

- 帆形：不对称的平衡斜桁四角帆。桅杆位于帆宽从前缘起约 1/4—1/3 处；上桁（帆顶）后端上翘，前低后高；后缘略外凸；帆骨保持水平或略上斜。每道帆骨尾端引一根控帆索，汇合成一组后引到甲板系缆点。现有的帆骨、分幅帆面、升帆索可以沿用，改的是轮廓和桅在帆面上的位置。
- 所有帆朝向一致（同一舷受风），避免前后帆互相穿插。
- 桅位：`rigStations` 中桅高最高的几根主桅（至少现在的第 3、4、5、6 项，按高度排序取最高的四根）移到中线（横向位置 0）；只有首、尾和较矮的辅桅可以偏置，偏置量不超过 ±0.15 船宽。首桅可以向前倾约 5°—10°。
- 桅回到中线后会与中线上的舱口、船楼冲突。`tools/check-fleet.mjs` 要求桅杆避开舱口和船楼、舱口是真实开口——通过调整舱口和桅的纵向位置或把舱口分到桅的两侧来解决，**不要删除或放宽这些断言**。五类船的桅位都从同一张 `rigStations` 取，逐一确认。
- `tools/blender/refine-superstructure.py` 及底稿里的桅座、桅夹、帆索跟随新的桅位。

### 5 新增形制断言

在 `tools/check-fleet.mjs` 加上（五类船、两种尺度都检查）：

- 艉封板顶部宽度 ≥ 0.55 B；船首封板顶部宽度在 0.28 B—0.42 B 之间；
- 艉封板上缘的 X 坐标比下缘更靠后；
- 舯部最大宽度与 B 相差不超过 3%；
- 桅高最高的四根桅 `|z| < 0.01 B`；任何桅 `|z| ≤ 0.15 B`；
- 舵叶下缘低于船底（`y < -D`）；`userData.rudderStock` 为有限正数；
- 每面帆的桅位在帆宽前缘起 0.2—0.38 之间（需要在 `layout` 或 `userData` 里暴露帆的前后缘位置）。

`tools/check-blender-ships.mjs` 如有对应的布局或坐标断言，同步更新，使 Blender 模型满足同样的艉宽、桅位条件。

  - 方艉、尖底、多重隔舱：福船类型的考古实物比较（泉州湾宋代海船），**不是**郑和船的直接证据；

  - 舵杆 11.07 米：出土实物，但与本页两套尺度的对应关系未定。
