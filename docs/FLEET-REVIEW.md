# 舰队复原评审意见（2026-11-04）

评审对象：`origin/main` 4739af9（舰队复原 C1—C5 与 Blender 宝船样板）。看了 FLEET-PLAN、FLEET-VALIDATION、`js/fleet-data.js`、`three/*.js`、`fleet.html`、三张 Blender 检查图，并在浏览器中检查了单船、剖视、侧视、第一次船队（夜间）和手机宽度。

总体：证据分级做得很扎实，史载、研究解释、建模假设分开保存，页面上也写明了边界，这是全站最严谨的一部分。下面的意见按优先级排列，编号便于逐条回复。

## 一、形制（建议优先处理）

1. **艉部应为方艉。** 泉州湾宋代海船等福船系出土实物的复原普遍是尖底、方艉（艉封板），艉楼伸出封板之上，舵从艉部的舵承垂下。现在的模型首尾都收成尖圆形，侧视时更像西式船。这一条有考古实物支撑，比九桅、三层楼的争议小，改动收益最大。建议：艉封板宽约为船宽的一半以上、向后上方倾斜，舵杆穿过艉部开槽的舵承，可升降。
2. **用舵杆校核舵的比例。** 1957 年南京宝船厂遗址出土铁力木舵杆，长 11.07 米。建议在两套尺度下量一下模型的舵杆长度，与它对照，写进"艉舵"构件说明；目前的舵看上去偏小。
3. **硬帆的形状。** 中式硬帆是平衡斜桁四角帆：桅杆位于帆宽前部约 1/4—1/3 处，上桁斜向上翘，后缘略外凸，每道帆骨尾端各引一根控帆索，再汇成一组。现在的帆面大致以桅为轴左右对称、顶边水平，侧视容易读成纵向挂的横帆。建议改成不对称、斜顶的帆形；精修样板的帆骨和汇合控帆索可以直接沿用。
4. **主桅在中线上。** 偏离中线的一般是首、艉和舷侧的小桅。`rigStations` 中最高的第 4、5 根主帆被放在 ±0.24 船宽处，建议移回中线，只让辅桅偏置；首桅可以略向前倾，这是福船常见的特征。
5. **船楼观感。** 三层平顶、四面挑出通透栏杆，看起来接近现代多层建筑。在保留"三层"假设的前提下，可以让楼层逐层后退，四周改为实心护板（女墙），屋顶加小坡度（卷棚或单坡），窗改为格扇。这些都属于建模假设范围内的调整，不增加新的史实断言。
6. **九面大帆在侧视中几乎连成一片。** 61.2 米方案的问题尤其明显。建议辅帆按桅高等比缩小，或增加"落帆"开关，便于看清船体和船楼。

## 二、页面与工程

7. **`fleet.html` 的 `<head>` 与其他页面不一致。** 缺少字体链接和 `viewport-fit=cover`，页面标题因此退回系统字体。`css/fleet.css` 里有全局的 `*`、`body`、`button`、`select` 规则，会覆盖 `base.css`，建议都限定在 `.fleet-page` 之内。
   - 页眉印章错位的根因在 `base.css`：印章原用竖排，网络字体加载失败时（国内访问 Google Fonts 时常如此）会错位。已在本次提交中修复，改为不依赖字体的两行排法，各页面自动生效。
8. **代码可读性。** `css/fleet.css` 和 `three/*.js` 中有 15 行超过 300 字符的压缩写法，与项目其他文件不一致，不利于审阅和交接。建议用 prettier 格式化后提交，压缩留给构建步骤。
9. **仓库体积。** 本轮新增约 9 MB 二进制（三张检查图 4.7 MB、两个 GLB 3.4 MB、`.blend` 1.2 MB）和约 6.5 MB 的 `dist/` 构建产物，而 `dist/` 每次重建都会再进一次 git 历史。建议：
   - `dist/` 加入 `.gitignore`，发布时放 GitHub Release 附件或单独的发布分支（此前我提交的 `dist/zheng-he-voyages-standalone.html` 也一并处理）；
   - 检查图改为压缩 JPEG（约 200 KB）放在 `docs/`；
   - GLB 用 gltf-transform 做 weld、dedup 和量化（KHR_mesh_quantization，three.js 原生支持，不需要额外解码器），体积预计可减半以上；
   - `.blend` 可考虑 Git LFS。
10. **用语统一。** 舰队视图写"第1次船队""第1次"，全站其他地方都写"第一次"。
11. **手机端热点标签重叠。** 例如"船体与龙骨"被"水密隔舱"遮住。建议窄屏只显示编号圆点，点开再显示名称。
