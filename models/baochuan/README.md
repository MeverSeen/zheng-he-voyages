## 日常编辑

1. 打开 `baochuan-master.blend`。全船位于 `Baochuan_full` 集合，剖视位于 `Baochuan_section` 集合（默认隐藏）。构件仍分船壳、桅帆、隔舱、舵、锚、甲板船楼六组。
2. 编辑控制网格或增加普通造型修改器。完整与剖视目前是两个独立构件树，共同构件的修改需同步处理；导出不会猜测任意新构件如何剖切。
3. 保留根对象 `metadata` 和构件组 `part` 自定义属性。大幅移动舱口、梯口、门洞或改变尺度时，也要同步相应布局数据；检查脚本会核对其中的开口和尺寸。
4. 保存母版，运行 `npm run model:export`、`npm run check`、`npm run build`。模型没有通过面数或来源一致性检查时，不会静默发布新产物。
5. 可运行 `npm run model:render` 检查母版与实际GLB。渲染与导出均不会保存母版。

Blender 文件采用米制、Z向上；导出的GLB为Y向上，船首始终为+X。不要在导出后对网页模型额外整体缩放。

## 修改器与网页简化

| 名称前缀 | 母版 | 网页导出 |
| --- | --- | --- |
| `DETAIL_` | 显示高细节，例如倒角、细分 | 不应用到网页网格 |
| `WEB_` | 编辑时应隐藏 | 导出时启用，例如经过检查的简化修改器 |
| 其他名称 | 常规造型 | 保留并求值 |

初始母版的木构件有 `DETAIL_Timber edge rounding`，帆面有 `DETAIL_Sail surface smoothing`。这些修改器可继续编辑。决定主要外形的修改器应使用普通名称，不能误标成网页忽略的细节。网页输出以控制网格为基础；新增复杂几何后如超预算，需配置适当的 `WEB_` 简化，导出器不会为凑面数任意破坏门洞或索具。

当前木构倒角名称为 `DETAIL_Rounded timber edges`。船壳、隔舱和屋顶厚度属于普通构造，保留在网页中。前部辅帆三种状态通过父对象的 `sail_state` 属性区分；修改时须同步帆面、帆骨及索具，不能只缩放布面。`Access study figures` 下的人体参照默认隐藏，标记 `export_web=false`，不输出网页。

## 实际烘焙范围

当前将标有 `bake_normal` 的木构件和帆面分别烘焙到完整/剖视各一张1024×1024法线图及颜色图。母版的 `GrainUV` 用于程序材质；导出副本另建 `WebAtlas`，母版不被改写。烘焙按构件名称分组隔离，减少相邻构件干扰，可用自定义属性 `bake_group` 指定分组；收帆状态各自隔离，避免相互投射。

帆布在网页贴图中保留原有展开坐标再统一排布，避免折缝变成无法覆盖的细条。颜色从控制网格烘焙，法线从细节表面投射；未烘焙的小型程序木构使用已指定的基础颜色。颜色贴图与法线贴图都嵌入GLB，原图另存供检查。

这不是全船所有材质和几何的自动烘焙：帆面细分保留在母版中，网页使用控制网格和烘焙贴图；新增的特殊材质、位移和复杂细节需要另外设计烘焙方案。法线贴图只能影响表面光照，不会改变网页模型轮廓。

网页适配器保留UV与法线贴图，并在构件内部合并兼容材质。贴图由模型缓存统一管理，切换模型时不提前销毁共用纹理。

## 初始化与维护

- `npm run model:baseline`：从参数生成底稿；既不保存母版，也不输出GLB。
- `npm run model:init-master`：仅当母版不存在时创建；已有文件直接报错，防止覆盖编辑。2026-11-10 的宝船重新初始化为用户明确批准的一次性例外，先保留旧文件于版本历史并核对旧来源指纹；不得将此例外扩展到日常操作或其他船型。
- `npm run model:export`：读取已保存母版，生成临时网页副本、烘焙、检查两种状态后发布派生产物。母版指纹写入导出记录和GLB。
- `npm run model:check`：在临时目录进行重建和编辑传递测试，检查已有母版拒绝初始化、导出不改源文件。

导出器也支持显式 `--master` 和 `--out`，供临时副本检查。`--no-bake` 只允许写到独立测试目录，不能用于正式网页资产。构建会拒绝母版过期、文件指纹不匹配或测试用途的导出记录。

Blender 烘焙依据：[官方 Render Baking 文档](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)。历史形制依据与假设保持在项目的 `docs/FLEET-PLAN.md` 中。
